### Should fix

S1. **Local drafts aren't tied to the account, and account deletion doesn't clear them** (`features/blog-editor/localDraft.ts`, `NewBlogView.tsx`, `features/account/DeleteAccountDialog.tsx`).
- `clearLocalDrafts()` runs only in `SettingsView.leave()`. Two other paths skip it:
  - Account deletion (`deleteMyAccount`, then sign-out on the server) leaves `oq_blog_draft:*` on the device.
  - A session that ends any other way also leaves it: expiry, signed out from another device, or `finishDeletionOnSignIn`.
- Entries carry no user key, so `NewBlogView` resumes `oq_blog_draft:new` for whoever is signed in next. Person B would then:
  - see A's unsent text;
  - save it as B's blog (the key was never used, so `create_blog` accepts it);
  - and, through `useBlogPhotos` → `indexedDbStore.list(key)`, upload A's pending photos into B's folder (`photoFolder = ${B}/${key}`).
- This needs a shared phone and an unsent offline draft, so it's rare. But it leaks one person's writing and photos to another account, and leaves a deleted account's text on the device (PRD privacy: "Deleting the account deletes the user's … drafts").
- Fix:
  - Store `userId` in each entry and in the `:new` pointer (`{ key, userId }`). `NewBlogView` and `useBlogAutosave` then ignore and remove entries for another user.
  - Call `clearLocalDrafts()` in `DeleteAccountDialog` on success.
- Add `localDraft.test.ts` cases: another user's `:new` is not resumed.
- The leftover IndexedDB photos are the accepted R7, but the resume path must not adopt them for another user.

S2. **Back navigation after the first save may reopen an empty composer** (deviation 2: `useBlogAutosave.onCreated` uses `window.history.replaceState`).
- Keeping the composer mounted while typing is right. But the App Router copies its internal state into the replaced entry, so that entry still holds the `/blogs/new` route tree.
- When the writer comes back to that entry with Back, from "Create a Quest" in the Link sheet (PRD B3 flow) or from the share screen, Next may restore `/blogs/new` from its router cache instead of loading `/blogs/{key}/edit`.
- `NewBlogView` would then make a **new key**, because `forgetNewBlogKey` already ran, and fire `blog_create_started` again. The writer would see an empty composer while their draft is safe on the server.
- I couldn't run this.
- Fix: leave the composer with a full navigation once the rows exist: `window.location.assign('/quests/new?source=blog_link')` in `LinkQuestRow.createQuest`, and the same for Post's `router.push` to the share screen. Or have `NewBlogView` check `location.pathname` on mount and `router.replace` to the edit page when it isn't `/blogs/new`.
- Add it to the UX test (below).

S3. **Photo tiles block page scrolling on phones** (`PhotoThumb.tsx`: `touch-none` on each tile; `PhotoRow.startDrag` on `pointerdown`).
- With 4–10 photos the grid fills a large part of the screen. A finger that lands on a tile to scroll the page starts a reorder instead, and `touch-action: none` stops the page from scrolling.
- Fix: start the drag after a short hold, about 300 ms without movement (the usual pattern), with `touch-action: pan-y` until then. Or drag only from a handle.
- The Move left/right buttons already cover keyboards and screen readers.

S4. **Preview shows a linked Quest card readers won't see** (`BlogPreview.tsx`: `linkedQuest?.path && <QuestCardView …>`).
- PRD B6 says "I see the blog as a reader would". Readers never see a private Quest's card, and under D12 (PRD change 4) readers of a public blog don't see an unlisted Quest's card either.
- Fix: in Preview, show the card only for a public Quest, or an unlisted Quest when the blog is unlisted (`store.visibility`). Otherwise show the writer's note "Your linked Quest isn't visible to readers", as BL-04's owner view will.
- The preview card is also a live link, so tapping it leaves the composer mid-edit (it saves on unmount). Render it without `href` in Preview.

S5. **The bare title and body have a low-contrast placeholder as their only visible label** (`design-system/components/TextField.tsx`, `TextArea` with `bare`: `sr-only` label + `placeholder:text-ink-subtle`).
- `ink-subtle` is `#9ca3af`, about 2.5:1 on white. In `bare` mode the placeholder is the only visible cue for "Title" and the body prompt.
- This also bends `TextField.tsx`'s own rule: "The label is always visible (never placeholder-only)".
- `bare` also sets `outline-none`, so the only focus indicator is the caret.
- Fix: use `placeholder:text-ink-muted` in `bare` (≥ 4.5:1, if the token is as dark as its use elsewhere suggests). Add a subtle focus cue in `bare`, such as a bottom border on `focus-visible`.
- The design-system rule in this file's header should either allow `bare`, with a reason, or not use it. The CTO or design owner decides that.

S6. **"Create a Quest" from an empty composer leaves an empty "Untitled blog"** (`LinkQuestRow.createQuest`: `saveNow({ force: draftSavedAt === null })`).
- On an empty composer, force-saving creates the rows (an empty `create_blog`). The writer leaves for the Quest flow, and the empty draft stays in their lists (`list_my_blogs`) as "Untitled blog".
- PRD B3 says "it saves the blog draft first", and there's nothing to save.
- Fix: force only when `hasContent(document)`. Same check for `PlaceRow`: there the rows are needed for `searchBlogPlaces`' owner check, and a chosen place is content, so that one is acceptable.

### Notes

N1. **Deviation 4: the `blog_link` source isn't recorded.** `quest_draft_created.source = blog_link` falls back to `create_menu`, so Quests started from a blog are counted as Create-menu starts. Add `blog_link` to `QuestCreateSourceSchema` (`lib/analytics/sources.ts`) in a small follow-up. The taxonomy CSV already lists the value.

N2. **Deviations 1, 3, 5, 6, 7 are accepted.**
- 1: `*.test.ts` with `renderToStaticMarkup`, because `vitest.config.ts` includes only `*.test.ts`.
- 3: one vanilla store per composer.
- 5: the extra copy ("Cover", "Move left/right", place-sheet copy, "Couldn't save. Retrying.", "Couldn't post. Check your connection and try again.", the body counter from 9,000) needs the founder's OK. List it for Alok.
- 6: the 1.2 s "Saved as a draft." before closing.
- 7: `TextArea` in `TextField.tsx`, no new tokens.

N3. **Two tabs, both offline from the first keystroke on the same unsent key.** The second tab gets OQ410 → reloads the edit page → `chooseStartingDraft` (based on null + only the first save) restores and saves its own text over the first tab's. Nothing is lost (it's archived), and the first tab then conflicts. That's an edge of an edge; acceptable.

N4. **Title Enter key.** `enterKeyHint="next"` on a textarea: Enter inserts a newline, which `cutTitle` turns into a space. The keyboard shows "next" but doesn't move to the body. Minor: handle `Enter` in the title by focusing the body.

N5. **Gallery keyboard access.** `BlogGallery`'s scroll list (`<ul>` with `overflow-x-auto`) isn't focusable, so keyboard users can't scroll it. When BL-04 doesn't pass `onOpen`, add `tabIndex={0}` and an `aria-label`. The "1 / 4" counter is `aria-live` and announces on every swipe; consider `aria-live="off"` with `aria-label` on the section. Affects BL-04 more than BL-03.

N6. **`/create` now makes one `has_feature_access` call per visit** for every signed-in user. That's cheap, and a failure falls back to "Releasing soon" with only the error code logged. Fine.

### For the human UX tester (preview build, preview project with `grant_feature_access`)

The PRD's UX tests 1, 2, 4, 5, plus 6 (two tabs), and these risk checks from this review:
1. **Without access** (a second account with no grant): Create still shows "Releasing soon"; opening `/blogs/new` directly lands on `/create`.
2. **S2:** start a blog, type a sentence, wait for "Saved", then Link a Quest → (if empty) Create a Quest. Press Back twice to return. You should see your blog with your text, not an empty composer. Repeat with Post → share screen → Back.
3. **S3:** with 6+ photos, try to scroll the page with a finger on the photos.
4. **Offline:** turn on airplane mode mid-sentence; the status says "Not saved yet. You're offline."; keep typing, add a photo, turn it off; it saves and the photo uploads.
5. **Close:** close an empty composer (nothing appears under your blogs later). Close one with text ("Saved as a draft.").
6. **Preview:** link a private or unlisted Quest, post as Public, and compare Preview with what a signed-out reader sees once BL-04 lands (S4).
7. **iPhone:** after "Write a blog", the cursor is in Title; note whether the keyboard opens without a tap (R5).
8. **HEIC and large photos** from the camera roll: accepted and shrunk; a failed upload shows Retry/Remove and Post waits.
