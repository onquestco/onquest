### Should fix

S1. **Length limits count UTF-16 units, not code points** (`lib/blog/schema.ts`, `BlogDocumentSchema`: `title: z.string().max(BLOG_TITLE_MAX)`, `body: z.string().max(BLOG_BODY_MAX)`).
- `lib/blog/limits.ts` says "code points". Postgres `char_length` counts code points (migration 16, lines 15–16, 215). The spec's `TitleField` cuts at 100 code points (§2, B2 row). The app's own `charactersLeft()` uses `[...text].length`.
- zod `.max()` counts UTF-16 units, so every emoji or other astral character counts twice. Text near the limit that the composer and the database accept fails the action's input check with "Invalid input".
- Autosave would then retry every 5 s and never succeed, leaving only the local backup.
- An owner's draft stored by a direct RPC with 100 astral characters would also make `loadOwnBlog` throw (`BlogDocumentSchema.parse`).
- Why: the input schema must not be narrower than the stored limit (CLAUDE.md backward compatibility), and BL-03 will rely on this contract.
- Fix: `.refine((text) => [...text].length <= BLOG_TITLE_MAX)` (and the same for body). Add a `schema.test.ts` case with 100 emoji, which must pass, and 101, which must fail. The same applies to `BlogPlaceSchema.name` (60).

S2. **A blog titled "Blog", "Followers" or "Following" gets a `-trip` slug** (`features/blogs/blogSlug.ts` calls `slugify(title, 70, 'blog')`; `lib/slug.ts` applies `RESERVED_SLUGS` to every caller).
- The result is `/@riya/blog/blog-trip`.
- The reserved list exists for one-segment Quest URLs. Blog slugs sit after `/blog/`, so nothing needs reserving there, and "-trip" on a blog URL is wrong.
- Blog slugs never change after the first Post, so this has to be fixed before the first production grant.
- Fix: give `slugify` a way to skip the reserved check (e.g. `{ reserved: false }`), or have `firstBlogSlug` slugify without it. Add a `blogSlug.test.ts` case: "Blog" → `blog`.

S3. **A null `p_based_on` skips the conflict check in the database** (migration 16: `save_blog_draft` line 376, `publish_blog` 410, `set_blog_visibility` 486, `set_blog_comments` 512).
- They all compare with `live.saved_at::text <> p_based_on`. With null, the comparison is null, so no OQ409 is raised and the save goes through.
- The actions refuse null (`z.string().min(1)`), but a signed-in user calling the RPC directly skips rule 4 on their own rows. Nothing is lost, because the old row is archived, but the database should enforce 0001 rule 4 by itself.
- Fix: `if p_based_on is null or live.saved_at::text <> p_based_on` (or `is distinct from`). Add one `blogSave.test.ts` case per function.
- The Quest functions in migration 9 (lines 341, 380, 458, 480) have the same gap. That is pre-existing: open a follow-up task for them rather than widening this PR.

S4. **Server analytics events from the BL-01 task aren't fired** (builder's deviation 2). The events are `blog_draft_saved`, `blog_published` and `blog_managed`.
- Appendix A BL-01 lists them under Build. `trackServer` only accepts taxonomy names, and the taxonomy is regenerated in BL-02.
- That is acceptable, but it must not get lost. Add all three events and their call sites (`saveBlogDraft` with `shouldTrackDraftSave`, `publishBlog`, the ⋯ actions) to the BL-02 issue's acceptance criteria and Touches, and to the spec §12 BL-02 row.

- **Data rules, no-in-place-updates bullet:** it keeps the italic "*The current schema doesn't follow this yet; new work must, and the migration spec will fix the rest.*" This PR changes decision 0001's status to "Accepted and implemented". Replace the italic text with something like "*Implemented (spec A, migrations 8–9; blogs from 16). One leftover: the inert `for all` policies on legacy `photos`/`places` (decision 0001, Current gaps).*"
- **"Where things go":** the `features/` line already leaves out `explore, guides, home, legal, notifications, quests, shell`. Adding only `blogs, blog-editor` keeps it wrong. List the real folders.
- **Cache-tag bullet:** "`blog-url:{handle}/{slug}` (`blogUrlTag()`, old and new handle)" is true for profile saves and deletes. But Post and visibility refresh only the current handle (deviation 5, which is correct because old handles 308). Reword to "…(every handle on a handle change or delete)".

### Notes

N1. **`get_blog` returns `comments_on`, but `setBlogComments` refreshes only `blog-social`** (spec §4.2). The cached page row can therefore show the old value. BL-04 must take "Comments are off" from `get_blog_social`, not from `BlogData.commentsOn`, or `setBlogComments` must also refresh `blogUrlTag`. Put this in the BL-04 issue.

N2. **Two slug edge cases.**
- The `-N` suffix can push an unlisted slug past 77 characters (70 + 7 + "-2"). The `blogs.slug` check would then fail with an unmapped 23514, which surfaces as "Could not publish blog". This needs a random-token collision first, so it is negligible.
- Two simultaneous first Posts by the same writer with the same title can both pass the loop. One then fails on `unique (owner_key, slug)` with a raw 23505. Rare. A retry on 23505, or an advisory lock per owner in `publish_blog`, would close it.

N3. **`discardBlogDraft` race.** It checks `status === 'published'` and then calls `delete_blog`, which doesn't re-check the status. A Post from another tab in between would let a "discard" hard-delete a posted blog. Very unlikely. A `p_draft_only` guard in SQL would close it.

N4. **`getMyQuestsForLinking` loads every Quest's full `content`** only to count days. That is fine at friends-test scale. Later, select `jsonb_array_length(content->'days')` through a function, or limit the columns.

N5. **LLD §5.5 states the Quest conflict copy wrongly.** It now says the Quest editor shows "This draft was changed somewhere else. Reload." The code says "This Quest changed on another device" (`features/editor/EditorDraft.tsx:58`, `PublishSheet.tsx:20`). Fix the doc line.

N6. **`lib/supabase/database.types.ts` isn't regenerated** (deviation 6). Regenerate it once the migration is on preview, before BL-02 adds typed reads.

N7. **The `get_blog_quest` matrix has no other-owner case.** That case can't be built through the functions, because `publish_blog` drops it, and the `t.owner_key = b.owner_key` join is the backstop. That is acceptable.
