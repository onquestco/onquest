### Should fix

S1. **The comment count stops at 100** (`features/blogs/BlogSocial.tsx`: `const count = comments.length`). `get_blog_social` returns at most the 100 newest comments but the full `comment_count`, so a blog with 140 comments says "100 comments". Use the provider's `commentCount` from `initial`, kept in step with `addComment`/delete. The Quest page shows no count, so this is new.

S2. **The writer's own visits count as reads** (`LiveBlogSocialProvider.useBlogViewed`, `BlogPageArticle` `useReadEnd(…, trackReading)`).
- `trackReading` is off only on `/blogs/[key]`. A writer who opens their own public link (the share screen, profile, feed) fires `blog_viewed` and `blog_read_end` like any reader.
- At friends-test scale, writers re-reading their own blog skew read-through and Blog-to-Quest.
- Fix: skip both when `viewer.isOwner` (known before `blog_viewed` fires, since it waits for the viewer). For `useReadEnd`, pass `trackReading && !viewer?.isOwner`.

S3. **Follow on a blog is counted as a Quest follow** (`WriterRow.tsx`: `source="quest"`, with the comment "user_followed.source has no blog value yet"). Follows from blogs become indistinguishable from follows from Quests. Add `blog` to `user_followed.source` in the Taxonomy sheet and the CSVs, then pass it. Small; it can go with the BL-03 N1 follow-up (`quest_draft_created.source = blog_link`).

### Notes

N1. **The `robots.ts` change is correct.**
- `allow: ['/', '/b/*/*/opengraph-image']` lets link-preview bots that honour robots.txt fetch the OG image, which Next serves from the internal `/b/…` route, while `/b/` pages stay disallowed. The longer, more specific rule wins under RFC 9309 and Google's matching.
- The canonical pages (`/@h/blog/s`) are unaffected.
- `/blogs` stays disallowed.

N2. **Links in blog text** (BL-03 `BlogBody`): `rel="nofollow ugc noopener"` matches the spec, which doesn't ask for `noreferrer`. The site's `Referrer-Policy: strict-origin-when-cross-origin` already keeps unlisted paths from other hosts. No change needed.

N3. **Photo viewer markup.** `BlogPhotoViewer` is a native modal `<dialog>` (Escape and Android back close it, focus stays inside, Close is autofocused). Its `<img>`s are server-rendered inside a closed dialog and lazy unless they're next to the tapped one, so they cost no bandwidth until opened. The duplicate images in the HTML are harmless for SEO.

N4. **Private and removed links return HTTP 200 with the message**, not a 404, exactly as the Quest page does today (`app/(public)/u/[handle]/[slug]/page.tsx`). docs/03 §C.2 says "Real 404s for missing/private trips". That's a pre-existing gap for both pages; `noindex` is set, so search is unaffected. If changed, do it for both in one place.

N5. **The owner view's comments switch comes from the live row** (`getOwnBlogPage`: `commentsOn: own.commentsOn`). Correct: never cached and newer than `blog-social`. Readers get `commentsOn` from `get_blog_social` (`BlogSocial` via `useQuestSocial`), never from `BlogData.commentsOn`, so issue #24 N1 is resolved.
